NUEVA NORMA

Tras el último incidente descubrimos que alguien activó el FTP anónimo «temporalmente, para las pruebas». Nadie sabe quién lo hizo, ni cuándo, ni cómo era la configuración anterior.

No puede volver a pasar. Los scripts de bastionado del servidor viven en una carpeta sin historial en ~/scripts-blindaje. Vais a ponerlos bajo control de versiones con Git y a trabajar con ellos como un equipo profesional: commits con autor, ramas, fusiones y un servidor compartido.

Los tickets os llegarán de uno en uno. Algunos compañeros también tocarán el repositorio… no siempre con acierto.

Cómo funciona

  • 📋 Tickets de uno en uno 30 misiones en 5 fases, de git init al trabajo en equipo con un servidor remoto.
  • ⌨️ Git de verdad add, commit, branch, merge, push, pull, stash, revert… con sus opciones y mensajes reales. Y nano para editar.
  • 🌿 Mira dentro del repositorio La pestaña «Repositorio» dibuja el grafo de ramas y las tres áreas de Git en tiempo real.
  • 🏅 XP, niveles e insignias Las pistas ayudan, pero reducen la recompensa. Subir secretos al historial sale caro.
Empezar desde

Si empiezas en una fase posterior, el repositorio se prepara automáticamente con las fases anteriores resueltas (esas misiones no suman XP).

          ❓ Guía rápida de Git

          Las tres áreas de Git

          ÁreaQué esCómo se llega
          Directorio de trabajoLos ficheros que ves y editasEditando (nano, echo, sed…)
          Área de preparación (staging, índice)Lo que entrará en el próximo commitgit add
          Repositorio (historial)Los commits: fotos del proyecto con autor, fecha y mensajegit commit

          Configurar y empezar

          git config --global user.name "Nombre" · user.email
          Tu identidad: aparece en cada commit. Consulta la configuración con git config --list.
          git init -b main
          Convierte la carpeta actual en un repositorio con la rama principal main.
          .gitignore
          Fichero con patrones (uno por línea, admite *) de ficheros que Git no debe seguir. Compruébalo con git check-ignore -v <fichero>.

          El ciclo de trabajo

          git status · git status -s
          Qué ha cambiado y en qué área está. Úsalo siempre que dudes: además te sugiere los comandos.
          git add <fichero> · git add .
          Prepara cambios (también borrados) para el próximo commit.
          git commit -m "mensaje" · git commit -am "mensaje"
          Crea un commit con lo preparado. Con -a prepara antes los ficheros ya seguidos. Sin -m abre el editor.
          git diff · git diff --staged
          Diferencias sin preparar (trabajo ↔ preparación) y preparadas (preparación ↔ último commit).
          git log --oneline --graph --all · git show <commit>
          Historial en forma de grafo y detalle de un commit. Referencias útiles: HEAD, HEAD~1, main, origin/main, un hash corto.
          git rm <fichero> · git mv <origen> <destino>
          Borra o renombra un fichero y prepara el cambio a la vez.

          Deshacer

          Quiero…Comando
          Descartar cambios sin preparar de un ficherogit restore <fichero>
          Sacar un fichero del área de preparacióngit restore --staged <fichero>
          Rehacer el último commit (no compartido)git commit --amend
          Deshacer commits locales conservando los cambiosgit reset HEAD~1 (--soft los deja preparados)
          Volver a un commit y tirar todos los cambiosgit reset --hard <commit> ⚠
          Deshacer un commit ya compartidogit revert <commit>
          Recuperar algo «perdido»git reflog y git reset --hard HEAD@{n}
          Guardar cambios a medias sin commitgit stash · git stash list · git stash pop

          Ramas y fusiones

          git branch · git branch -vv · git branch -a
          Lista las ramas (con -vv, también su rama remota y si van por delante o por detrás).
          git switch -c <rama> · git switch <rama>
          Crea una rama y se cambia a ella · cambia de rama. Equivalen a git checkout -b y git checkout.
          git merge <rama> · git merge --abort
          Integra otra rama en la actual (avance rápido o commit de fusión). Si hay conflictos: edita el fichero, quita las marcas <<<<<<< ======= >>>>>>>, y haz git add + git commit.
          git branch -d <rama>
          Borra una rama ya fusionada (-D fuerza el borrado aunque se pierdan commits).
          git rebase <rama> · git cherry-pick <commit>
          Reaplica tus commits encima de otra rama · copia un commit concreto en la rama actual.

          Trabajo en equipo (remotos)

          git remote add origin <url> · git remote -v
          Registra el servidor compartido.
          git push -u origin main · git push
          Sube commits. -u enlaza la rama local con la remota (upstream).
          git fetch · git pull
          fetch descarga y actualiza origin/main sin tocar tu rama; pull descarga e integra (--rebase o --no-rebase si las ramas han divergido).
          git tag -a v1.0 -m "mensaje" · git push origin v1.0
          Crea una etiqueta anotada y la sube (las etiquetas no viajan con un push normal).

          Terminal y editor

          ls -la · cat · echo "texto" > fichero (crea) · >> (añade) · touch · rm · mv · cp · sed -i 's/viejo/nuevo/' fichero · sed -i '/patrón/d' fichero · grep · nano fichero · man git-commit · git help <comando> · history · clear. Encadena con &&, || o ; y filtra con | grep, | head…

          nano: Ctrl+O guardar · Ctrl+X salir · Ctrl+K cortar línea · Ctrl+U pegar. Terminal: ↑ ↓ historial · Tab autocompletar · Ctrl+L limpiar · Ctrl+C cancelar la línea. Con la línea vacía, Tab sale de la terminal.
