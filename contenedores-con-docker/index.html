Sacar la intranet de un servidor artesanal y meterla en contenedores

DE: Nayra Suárez · Responsable de Sistemas PARA: Ana Betancor ASUNTO: Migración de la intranet a contenedores
PROYECTO

La intranet funciona, sí. Pero está montada a mano sobre el servidor: paquetes instalados en su día, configuración retocada por tres personas distintas y nadie capaz de reproducirla si mañana hay que moverla.

Te he preparado srv-docker con el motor recién instalado y sin una sola imagen descargada. Empieza por lo pequeño: una imagen oficial, un contenedor, y de ahí hacia arriba hasta levantar toda la pila con un solo fichero.

Y hay una cosa que quiero que te quede grabada: lo que un contenedor escribe dentro de sí mismo desaparece con él. Los datos van en volúmenes, siempre.

Cómo funciona

  • 🐳 26 tareas en 5 fases De docker pull a docker compose up, pasando por construir tu propia imagen.
  • ⌨️ Órdenes reales run, ps, logs, exec, build, volume, compose… con sus opciones y sus errores de verdad.
  • 💾 Errores que enseñan La base de datos que no arranca por falta de una variable, el puerto ya ocupado, el volumen que salva los datos.
  • ⚠️ No pierdas los datos Borrar un volumen o levantar una base de datos sin él resta XP y queda anotado.

Si empiezas en una fase posterior, el servidor se prepara automáticamente con las fases anteriores resueltas (esas tareas no suman XP).

        Decisiones arriesgadas

          ❓ Guía rápida de Docker

          Las tres palabras que hay que separar

          ConceptoQué es
          ImagenLa plantilla, de solo lectura. Se descarga o se construye. nginx:1.27
          ContenedorUna instancia en marcha de una imagen. Efímero: lo que escribe dentro muere con él
          VolumenAlmacenamiento que vive fuera del contenedor y sobrevive a su borrado

          Y una regla: pon siempre la etiqueta de versión. nginx:1.27 es reproducible; nginx (es decir, nginx:latest) es una ruleta.

          Imágenes

          docker images · docker image ls
          Las imágenes descargadas, con su repositorio, etiqueta, ID y tamaño.
          docker pull <imagen>:<etiqueta>
          La descarga del registro, capa a capa. Las capas que ya tengas no se vuelven a bajar.
          docker build -t <nombre>:<versión> .
          Construye una imagen a partir del Dockerfile del directorio. Ese punto final es el contexto: la carpeta que se envía al motor.
          docker rmi <imagen>
          Borra una imagen. Falla si algún contenedor la está usando.

          Contenedores

          docker run [opciones] <imagen> [orden]
          Crea y arranca. Las opciones van antes de la imagen.
          -d · --name <n> · --rm
          Segundo plano, nombre reconocible y borrado automático al terminar.
          -p <anfitrión>:<contenedor>
          Publica un puerto. El del anfitrión va primero. Un mismo puerto del anfitrión solo lo puede tener un contenedor.
          -e CLAVE=valor
          Variable de entorno. Muchas imágenes oficiales no arrancan sin las suyas.
          -v <volumen>:<ruta>
          Monta un volumen dentro del contenedor. Es lo que salva los datos.
          docker ps · docker ps -a
          Los que están en marcha, o todos, incluidos los parados. Un contenedor parado sigue existiendo.
          docker logs <c> · --tail 20
          La salida del contenedor. Aquí está el porqué de casi todos los contenedores que se caen al arrancar.
          docker exec <c> <orden> · -it
          Ejecuta algo dentro de un contenedor en marcha. Con -it … sh entras a una sesión interactiva.
          docker stop / start / restart / rm
          Ciclo de vida. rm se niega si está en marcha (salvo con -f).

          Datos y redes

          docker volume create <n> · ls · rm
          Volúmenes con nombre. rm falla si algún contenedor lo está usando, pero si lo borras, los datos no vuelven.
          docker network create <n> · ls
          Redes propias. Los contenedores de una misma red se ven entre sí por su nombre.

          El Dockerfile

          La receta de la imagen. Las instrucciones más habituales:

          InstrucciónQué hace
          FROMImagen de partida
          COPYCopia ficheros del contexto dentro de la imagen
          RUNEjecuta una orden al construir (crea una capa)
          EXPOSEDocumenta el puerto que usa (no lo publica)
          CMDQué se ejecuta al arrancar el contenedor

          Docker Compose

          Un fichero compose.yaml describe varios servicios con sus imágenes, puertos, variables y volúmenes. docker compose up -d los levanta todos con una red propia; docker compose ps los muestra y docker compose down los recoge. Los volúmenes con nombre no se borran con down: por eso los datos siguen ahí la próxima vez.
